## A. 電子郵件版

**收件者**：〔各開發科室主管、開發同仁〕
**副本**：〔資訊部主管、系統組〕
**主旨**：【新制上路】連線異常查詢改採線上登記，自 〔115/○/○〕 起實施

---

各位同仁，午安：

為了讓連線異常的問題**更快被查出來、也更快回覆各位**，資安組自 **〔115 年 ○ 月 ○ 日（星期一）〕** 起，
將「連線不通、疑似被擋」類的查詢，由口頭洽詢改為**線上登記**，說明如下。

### 一、登記方式

請至 NAS 線上表單登記：

> 📄 **〔連線異常查詢案件登記.xlsx〕**
> 路徑：〔`\\NAS_IP\共用資料夾\資安組\`〕
> 或於瀏覽器開啟：〔http://〔NAS_IP〕:5000 → File Station → 上述路徑 → 按兩下開啟〕

在最後一列空白列**往下新增一筆**即可，藍色標題的欄位是請各位填寫的部分，深藍色欄位由資安組回填，**請勿修改他人的資料列**。

「登記時間」欄請這樣填：按 **`Ctrl` + `;`**（帶出今天日期）→ 按一下**空白鍵** → 按 **`Ctrl` + `Shift` + `;`**（帶出現在時間）。
這個時間就是您的**排隊順序**，請務必填當下時間。

### 二、必填資訊（8 項，缺一項無法受理）

| # | 欄位 | 說明 |
|---|---|---|
| 1 | 來源 IP（含網段） | 例：開發 Server `192.168.251.x` |
| 2 | 目的 IP 或網域 | |
| 3 | 目的通訊埠（Port） | |
| 4 | 通訊協定 | TCP／UDP／HTTP／HTTPS／其他 |
| 5 | **錯誤訊息原文** | **請直接複製貼上完整訊息，不要轉述或摘要** |
| 6 | 發生時間 | 精確到分鐘（資安組要靠這個時間去撈設備日誌） |
| 7 | 用途說明 | 這條連線是做什麼用的 |
| 8 | 預計使用期間 | 一次性／長期 |

這 8 項不是為了增加手續 —— 它們**正好就是查防火牆與資安設備日誌時，一定要有的條件**。
過去用口頭詢問，同事平均要來回問三、四次才問齊，光是問就先花掉半小時；
資訊一次到位，多數案件可以在**幾分鐘內**得到答覆。

**其中「錯誤訊息原文」最關鍵**：`connection timed out`（逾時）和 `connection refused`（被拒絕）看起來都是「連不上」，
但前者通常是被防火牆丟包、後者往往是目的主機的服務沒開 —— 光憑一句「連不上」是查不出來的。

### 三、處理方式

1. **案件一律依登記時間由舊到新處理**，先登記的先辦。
2. 登記資料不完整者，資安組會在該列備註欄註明缺漏項目，**補齊後才會開始計時排隊**。
3. 資安組查明後，會在同一列回填「實際原因」與「責任單位」；
   若判定屬**系統組**（防火牆政策、FortiADC、路由交換器、專線等）或**應用程式本身**的問題，
   會在該列註明，請各位再依該結果向對應單位提出。
4. **自即日起不再受理口頭洽詢**（含當面、電話、通訊軟體私訊）。
   若情況確實特殊、影響營運中的正式環境，請先完成登記，再以電話告知資安組，我們會優先處理。

### 四、為什麼要這樣做

資安組目前的人力，同時負責資安設備、監控與規範作業。
過去每一次「臨時被叫住去查一下」，中斷的不只是幾分鐘，而是整段正在進行的工作；
而查完之後沒有任何紀錄，下次同樣的問題還是得從頭再查一次。

改為登記之後：

- 各位**看得到自己排在第幾位**，不必反覆追問進度；
- 資安組可以連續處理，**整體等待時間會縮短**；
- 三個月後我們會累積出「**症狀 → 該找哪一組**」的對照表，並主動發給各位，
  屆時多數狀況各位可以**自行初步判斷該找誰**，不必再繞一圈。

造成的不便，敬請見諒；有任何問題歡迎與我們討論。

〔資安組　○○○〕
分機 〔○○○〕
