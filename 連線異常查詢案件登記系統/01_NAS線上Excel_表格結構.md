# 一、NAS 線上 Excel 表格結構（Phase 1 登記端）

> 對象：資安組建檔人員
> 檔案：Synology NAS ➜ Synology Office 試算表，檔名建議 **`連線異常查詢案件登記.xlsx`**
> 這份檔案共有 **2 個工作表**：`案件登記`、`選項`
>
> **最快的做法**：直接把附的 **`案件登記_範本.xlsx`** 上傳到 NAS 的共用資料夾，
> 在 File Station 對它按右鍵 →「以 Synology Office 開啟」，欄位標題、欄寬、下拉選單都已經設定好，
> 不需要照下面的步驟手動建。下面的內容是**給你核對與日後修改用的規格**。

---

## 1. 工作表一：`案件登記`

### 1-1 欄位標題列（第 1 列）— 可直接複製貼上

在 A1 儲存格貼上下面這一行（是用 Tab 分隔的，貼上後會自動分散到 A1～V1）：

```
案件編號	登記時間	申請人／單位	問題類型	問題類型其他說明	來源 IP（含網段）	目的 IP 或網域	目的通訊埠	通訊協定	錯誤訊息原文	發生時間	用途說明	預計使用期間	實際原因	實際原因其他說明	責任單位	責任單位其他說明	處理耗時	是否重複案件	處理狀態	結案時間	備註
```

### 1-2 欄位一覽

| 欄 | 欄位名稱 | 填寫者 | 型別 | 說明 |
|---|---|---|---|---|
| A | 案件編號 | 登記人 | 文字 | 建議格式 `C` + 年月 + 流水號，例：`C2608001`。可留白。 |
| B | **登記時間** | 登記人（見 §4） | 日期時間 | **決定處理順序**，格式 `yyyy/mm/dd hh:mm` |
| C | 申請人／單位 | 開發人員 | 下拉＋可自由輸入 | 規格 §5-2 |
| D | 問題類型 | 開發人員 | 下拉單選 | 規格 §6.1 |
| E | 問題類型其他說明 | 開發人員 | 文字 | D 欄選「其他」時必填 |
| F | 來源 IP（含網段） | 開發人員 | 文字 | 規格 §6.2，例：`192.168.251.21（開發 Server）` |
| G | 目的 IP 或網域 | 開發人員 | 文字 | 規格 §6.2 |
| H | 目的通訊埠 | 開發人員 | 數字 | 規格 §6.2 |
| I | 通訊協定 | 開發人員 | 下拉＋可自由輸入 | 規格 §6.2 |
| J | 錯誤訊息原文 | 開發人員 | 文字（長） | **請貼完整原文，不可轉述** |
| K | 發生時間 | 開發人員 | 日期時間 | 精確到分鐘，供查日誌 |
| L | 用途說明 | 開發人員 | 文字 | 這條連線做什麼用 |
| M | 預計使用期間 | 開發人員 | 下拉單選 | 一次性／長期 |
| N | 實際原因 | **資安組** | 下拉單選 | 規格 §6.3，**點選不打字** |
| O | 實際原因其他說明 | 資安組 | 文字 | N 欄選「其他」時必填 |
| P | 責任單位 | **資安組** | 下拉單選 | 規格 §6.4，**點選不打字** |
| Q | 責任單位其他說明 | 資安組 | 文字 | P 欄選「跨組」時必填 |
| R | 處理耗時 | **資安組** | 下拉單選 | 規格 §6.5，**點選不打字** |
| S | 是否重複案件 | 資安組 | 下拉（是／否） | 同一系統／同一人反覆詢問時選「是」 |
| T | 處理狀態 | 資安組 | 下拉單選 | `待處理`／`處理中`／`已結案` ← **控制台靠這欄判斷待辦** |
| U | 結案時間 | 資安組 | 日期時間 | 可留白 |
| V | 備註 | 資安組 | 文字 | 可留白 |

> **T 欄「處理狀態」是規格 §5 八欄之外新增的欄位。**
> 原因：規格 §7.1 要求控制台列出「尚未結案」的案件，但原本八個欄位沒有任何欄位能表示案件已否結案。
> 若這一欄留白，控制台會自動判斷：**N、P、R 三欄都填好 = 已結案**，否則視為待辦，所以就算忘了填也不會出錯。

### 1-3 表頭顏色的意思（範本已經上色）

| 顏色 | 意思 |
|---|---|
| 深灰 | 案件編號（登記人填） |
| 藍色 | **開發人員**要填的欄位 |
| 深藍 | **資安組**要填的欄位 |

## 2. 工作表二：`選項`（供使用者自行擴充）

### 2-1 欄位標題列（第 1 列）— 可直接複製貼上

```
申請人／單位	問題類型	通訊協定	預計使用期間	實際原因	責任單位	處理耗時	處理狀態
```

### 2-2 內容（第 2 列開始，每欄一組選項，可自行往下加）

| 欄 | 標題 | 起始內容 |
|---|---|---|
| A | 申請人／單位 | 核心系統科／網銀開發科／信用卡系統科／外匯系統科／數位金融科／委外廠商 |
| B | 問題類型 | 規格 §6.1 的 7 項 |
| C | 通訊協定 | TCP／UDP／HTTP／HTTPS／其他 |
| D | 預計使用期間 | 一次性／長期 |
| E | 實際原因 | 規格 §6.3 的 12 項 |
| F | 責任單位 | 規格 §6.4 的 4 項 |
| G | 處理耗時 | 5 分鐘內／15 分鐘／30 分鐘／1 小時／1 小時以上 |
| H | 處理狀態 | 待處理／處理中／已結案 |

### 2-3 擴充規則（很重要）

- 要新增選項：**在該欄最後一筆的下一列直接輸入**即可，登記表的下拉選單與控制台都會自動吃到，**不需要改任何程式**。
- **不要更動第 1 列的欄位標題**，控制台是靠標題文字辨認每一欄是哪一組選項的。
- **不要在選項中間留空白列**（空白列以下的項目會被忽略）。
- 責任單位第一項請維持以「**資安組**」三個字開頭 —— 控制台計算「非資安組責任占比」時，是看這三個字判斷的。
- 處理耗時可以自行加，例如加「`2 小時`」「`4 小時以上`」；控制台會自動把文字換算成分鐘（含「以上」者以 1.5 倍估算）。

## 3. 需要設定的資料驗證規則

在 Synology Office 試算表：選取整欄 →上方功能表 **資料 → 資料驗證** → 條件選 **清單（來自範圍）** → 貼上下表的來源範圍。

| 要設定的欄 | 條件 | 來源範圍（直接複製） | 允許自由輸入？ |
|---|---|---|---|
| C：申請人／單位 | 清單（來自範圍） | `='選項'!$A$2:$A$200` | ✅ 允許（新單位可直接打） |
| D：問題類型 | 清單（來自範圍） | `='選項'!$B$2:$B$200` | ❌ 只能選 |
| I：通訊協定 | 清單（來自範圍） | `='選項'!$C$2:$C$200` | ✅ 允許 |
| M：預計使用期間 | 清單（來自範圍） | `='選項'!$D$2:$D$200` | ❌ 只能選 |
| N：實際原因 | 清單（來自範圍） | `='選項'!$E$2:$E$200` | ❌ 只能選 |
| P：責任單位 | 清單（來自範圍） | `='選項'!$F$2:$F$200` | ❌ 只能選 |
| R：處理耗時 | 清單（來自範圍） | `='選項'!$G$2:$G$200` | ❌ 只能選 |
| T：處理狀態 | 清單（來自範圍） | `='選項'!$H$2:$H$200` | ❌ 只能選 |
| S：是否重複案件 | 清單（自行輸入） | `是,否` | ❌ 只能選 |

設定範圍請套用到 **第 2 列到第 1000 列**（例：`D2:D1000`）。
「允許自由輸入」＝ 在資料驗證視窗中**不要**勾選「拒絕輸入無效資料／顯示錯誤警告」。

### 其他建議設定

| 項目 | 設定 |
|---|---|
| B、K、U 欄格式 | 數字格式 → 日期時間 → `yyyy/mm/dd hh:mm` |
| H 欄格式 | 數字（整數） |
| 凍結 | 凍結第 1 列（檢視 → 凍結） |
| 篩選 | 對 A1:V1 開啟篩選 |
| 共用權限 | 開發人員：**可編輯**；建議在 Synology Drive 對此檔開啟「版本歷程」以便追溯 |

## 4. 「登記時間」怎麼填（Phase 1 的限制，請先看這段）

規格 §5 希望「登記時間」由系統自動產生。**Synology Office 試算表沒有內建自動時間戳記**，
而且 `=NOW()` 這類公式每次開檔都會重算，會讓排序失真，**所以不能用公式**。

Phase 1 的做法（已寫入通知稿）：

1. 開發人員登記時，在 B 欄按 **`Ctrl` + `;`**（輸入今天日期）→ 按一下**空白鍵** → 按 **`Ctrl` + `Shift` + `;`**（輸入現在時間）。
2. 只能填當下時間，不得回填。
3. 資安組收案時，若對登記時間有疑義，可用 Synology Drive 的**版本歷程**查該列是何時被加進來的。

Phase 2 移到 Web Station 之後，登記時間改由系統自動寫入資料庫，使用者完全無法修改，此限制即解除。

## 5. 給 Phase 2 銜接用（開發時請沿用）

控制台與未來的 PHP／MariaDB 程式使用同一組欄位代碼，**中文欄名與英文代碼一一對應、不要更動**：

| 中文欄位 | 資料代碼（Phase 2 資料表欄名建議） | 型別 |
|---|---|---|
| 案件編號 | `case_no` | VARCHAR(20) |
| 登記時間 | `registered_at` | DATETIME（系統自動） |
| 申請人／單位 | `applicant` | VARCHAR(50) |
| 問題類型 | `issue_type` | VARCHAR(100) |
| 問題類型其他說明 | `issue_type_other` | VARCHAR(255) |
| 來源 IP（含網段） | `src_ip` | VARCHAR(100) |
| 目的 IP 或網域 | `dst_ip` | VARCHAR(255) |
| 目的通訊埠 | `dst_port` | VARCHAR(20) |
| 通訊協定 | `protocol` | VARCHAR(20) |
| 錯誤訊息原文 | `error_msg` | TEXT |
| 發生時間 | `occurred_at` | DATETIME |
| 用途說明 | `purpose` | VARCHAR(255) |
| 預計使用期間 | `usage_period` | VARCHAR(20) |
| 實際原因 | `root_cause` | VARCHAR(100) |
| 實際原因其他說明 | `root_cause_other` | VARCHAR(255) |
| 責任單位 | `owner_team` | VARCHAR(100) |
| 責任單位其他說明 | `owner_team_other` | VARCHAR(255) |
| 處理耗時 | `handling_time` | VARCHAR(20) |
| 是否重複案件 | `is_duplicate` | TINYINT(1) |
| 處理狀態 | `status` | VARCHAR(20) |
| 結案時間 | `closed_at` | DATETIME |
| 備註 | `note` | VARCHAR(255) |

選項清單在 Phase 2 建議建成一張 `options` 資料表：`group_key`（對應上表代碼）、`label`、`sort_order`、`enabled`，
內容直接由 Phase 1 的「選項」工作表搬過去即可，選項文字完全一致，歷史資料不需要轉換。
